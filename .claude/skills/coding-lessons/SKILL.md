# coding-lessons — 実装前に読む規律と失敗パターン

コード変更(実装・バグ修正・リファクタリング・レビュー)の着手前にこの skill を読む。記事2の5軸で構成する。学びが増えたら `learnings/` から昇格させて更新する。

## 1. 着手前チェック（記憶でなくリポジトリを読む）
- [ ] 対象ファイルと **呼び出し元** を実際に開いた（記憶・依頼文の推測で判断しない）
- [ ] 完了条件を観測可能な形で1行書けた（書けないなら理解不足 → 先に調べる）
- [ ] このリポジトリの規約を確認した: `CLAUDE.md`（§2 実行ポリシー / §3 Git / §4 デザイン連動 / §5 Figma）
- [ ] `components/` または `lib/design-tokens.ts` / `app/globals.css` に触るなら §4 のスタイルガイド更新義務が発火するか確認した
- [ ] Supabase / SQL / 認証 / 依存追加 / ビルド設定に触るなら §2-2「要承認」→ 実行前にサマリー提示

## 2. 失敗パターン（症状 → ありがちな誤り → 正しい一手）
> シード。再発 or 観測裏取りで `learnings/` から追記していく（目標10〜15件）。

1. **症状**: `app/globals.css` の `@theme` 編集がプレビューに反映されない
   → **誤り**: 編集が効いていないと思い込み別の場所を触る
   → **正しい一手**: Turbopack のキャッシュを疑い、ユーザーの明示承認を得てから `.next` を削除して再ビルド（memory: turbopack-theme-css-stale-cache）
2. **症状**: `components/` に新規コンポーネントを足したがスタイルガイドに出ない
   → **誤り**: 実装だけで完了とする
   → **正しい一手**: 同じタスク内で `app/styleguide/StyleguideLayout.tsx` に import + `<ComponentPreview>` を追加（CLAUDE.md §4）
3. **症状**: Supabase の型と実装がずれてビルドが落ちる
   → **誤り**: 手で型を書き換える
   → **正しい一手**: `npm run update-types`（`supabase gen types` → `src/types/supabase.ts`）で再生成
4. **症状**: コミットが commitlint で弾かれる
   → **誤り**: メッセージを推測で直して再試行
   → **正しい一手**: `<type>: <説明>`（type = feat/fix/refactor/style/chore/docs）に整形（CLAUDE.md §3-1）
5. **症状**: 「軽微な修正」のつもりが複数コンポーネントに波及
   → **誤り**: そのまま自動実行で進める
   → **正しい一手**: §2-2 の破壊的変更として扱い、サマリー提示 → 承認を得る

## 3. 意思決定分岐
- **非同期/並列で builder を起動する前の3問**: 誰がキャンセルするか / 誰が完了を待つか / エラーはどこへ返るか。3つ答えられないなら同期実行にする。
- **fable を呼ぶか**: CLAUDE.md §6-2 の3条件（設計の山場 / 失敗コスト大 / 未知構造）に該当するときだけ。該当しなければ opus/qa-verifier で足りる。
- **要承認か自動実行か**（CLAUDE.md §2）: 依存変更・スキーマ・認証・環境変数・ビルド設定・破壊的変更 → 要承認。迷ったら §0-3 で承認側に倒す。

## 4. 検証コマンド（このリポジトリの門）
1コマンドで実行し、実 stdout / exit code を観測する（「通るはず」で飛ばさない）:
```
npm run check    # tsc --noEmit → eslint → next build（約10秒・exit 0 が緑）
```
> 段を個別に走らせない。門は二値であることに意味がある（VERIFIED 2026-09-07: exit 0 / 10s / lint 0 errors）。
> 同じコマンドが CI（`.github/workflows/check.yml`）と Stop hook からも走る。
> テストスイートは現状なし（VERIFIED 2026-07-21）。テストが追加されたら `check` に `test` 段を足す。
> UI変更はプレビューで観測（`/preview` skill / preview_start）。

## 5. 学習ループ
- 作業で得た失敗・気づきは `learnings/` に1学び1ファイルで記録（`/learn` skill）。
- 昇格基準（2回以上再発 or 観測で裏取り済み or 一般化可能）を満たしたら、上記「2. 失敗パターン」へ移して重複を削除。
- 誤りと判明した lesson は削除する。
