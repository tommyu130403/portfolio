# research-lessons — 調査前に読む規律と失敗パターン

調査・リサーチ・事実確認を伴う作業の着手前にこの skill を読む。記事2の5軸で構成する。学びが増えたら `learnings/` から昇格させて更新する。

## 1. 着手前チェック（記憶でなく一次情報を読む）
- [ ] 問いを1文で書けた（曖昧なら scope を絞る質問を先にする）
- [ ] 一次情報（原典・公式ドキュメント・実データ）にあたる計画がある（要約の又聞きで結論しない）
- [ ] 何が「事実 / 仮定 / 不明」かを仕分ける前提で読む

## 2. 失敗パターン（症状 → ありがちな誤り → 正しい一手）
> シード。再発 or 観測裏取りで `learnings/` から追記していく（目標10〜15件）。

1. **症状**: 依頼文の「たぶんXが原因」を出発点に調べ、それを裏付ける情報だけ集める
   → **誤り**: 確証バイアス。人の推測を事実として受け取る
   → **正しい一手**: 推測は「仮定」欄に置き、反証も等しく探す
2. **症状**: 1つの検索観点だけで「見つからない=存在しない」と結論
   → **誤り**: 単一観点の見落とし
   → **正しい一手**: 観点を変えて多角的に掃引（用語・時期・主体・反対語）してから結論
3. **症状**: モデル/API の仕様を記憶で答える
   → **誤り**: 古い/誤った知識をそのまま出す
   → **正しい一手**: 公式ドキュメントを実際に取得して確認（`claude-api` skill 等）、未確認は「未確認」と明記
4. **症状**: 複数ソースを継ぎ接ぎして著作物を実質再構成
   → **誤り**: 著作権・要約義務の違反
   → **正しい一手**: 出典を明記し、要約は原典より十分短く別の表現にする

## 3. 意思決定分岐
- **fact-checker に fable を使うか**: 高リスク・不可逆・結論が広く波及する主張のときだけ（CLAUDE.md §6-2）。通常の裏取りは opus/WebSearch で足りる。
- **深さの判断**: 失敗コストが低く可逆なら軽い確認で進む。結論が意思決定を左右するなら一次情報まで遡る。
- **多観点掃引 → 統合 → 事実検証** の順で組む（researcher sonnet → synthesizer opus → fact-checker opus/fable）。

## 4. 検証手順（主張ごとに裏取り）
- 各主張に VERIFIED / REASONED / ASSUMED を付す。実際に一次情報で確認したものだけ VERIFIED。
- 出典 URL / 取得日を残す。取得できなかったものは「未確認」と書き、憶測で埋めない。
- 統合物は初見の読者として通読し、依頼原文と全要求を突き合わせる。

## 5. 学習ループ
- 得た失敗・気づきは `learnings/` に1学び1ファイルで記録（`/learn` skill）。
- 昇格基準（2回以上再発 or 観測で裏取り済み or 一般化可能）を満たしたら「2. 失敗パターン」へ移し、重複を削除。
- 誤りと判明した lesson は削除する。
