# 問い合わせフォーム(Contact)の SQL 適用手順

サイドメニューとログイン画面の「お問い合わせ」から送られた内容を貯める表を、dev → 本番の順に作る手順です。SQL はオーナーが Supabase の SQL Editor で流します。

## 用語

| 言葉 | 意味 |
|---|---|
| SQL Editor | Supabase の管理画面で SQL を流す画面(左メニューの「SQL Editor」) |
| Table Editor | Supabase の管理画面で表の中身を見る・消す画面(左メニューの「Table Editor」) |
| dev | 開発用のプロジェクト(`aemqzbsofprgmwtpfndf`) |
| 本番 | 公開サイトのプロジェクト(`kljlxjlbetaxhtxqzrdc`) |
| RLS | 表ごとの「誰が読める・書けるか」の決まり |

## 手順

| # | 作業 | 場所 | ここで止めたら |
|---|---|---|---|
| 1 | `supabase/migrations/20261109130000_contact_messages.sql` の全文を貼って Run | dev の SQL Editor | 表ができるだけで、画面には何も起きない |
| 2 | `supabase/data/20261109_contact_messages_verify.sql` を貼る。「1.」「2.」「3.」の各ブロックを 1 つずつ選んで(ドラッグで範囲選択して)Run し、コメントの期待値と見比べる | dev の SQL Editor | 同上 |
| 3 | 同じファイルの「begin;」から最後の「rollback;」までを選んで Run。エラーで止まらなければ通過(最後に取り消すので行は残らない) | dev の SQL Editor | 同上 |
| 4 | 1〜3 を本番でも行う | 本番の SQL Editor | 表があるだけ。画面はまだ古いので影響なし |
| 5 | PR を確認してマージし、公開(デプロイ)する | GitHub | — |
| 6 | 公開サイトのログイン画面の「お問い合わせ」から 1 件送る。本番の Table Editor の `contact_messages` に 1 行増えたことを確かめ、その行の左のチェックを入れて「Delete」で消す | 公開サイト・本番の Table Editor | — |

- 3 の前提: その環境に、期限内のゲストが 1 人以上いること。いなければ「4-0」のエラーで止まるので、先にゲストを発行してください。
- 1 は何度流しても安全です。表がすでにあれば作り直さず、権限・決まり・送信前の処理だけを同じ内容で作り直します。
- 本番の 1 を飛ばしてデプロイすると、送信ボタンを押しても「送信できませんでした」になります(保存先の表が無いため)。

## 届いた問い合わせの見方

本番の Supabase 管理画面 → Table Editor → `contact_messages`。サイトの管理画面(/admin)には一覧がありません。届いても通知は来ないので、定期的に見に行ってください。

- `user_id` が空の行はログイン前の人から、入っている行はログイン済みのゲストからの問い合わせです。
- `ip_hash` は送信元の接続元を変換した値です(IP アドレスそのものは保存しません)。件数の上限を数えるために使います。

## いたずら対策(24 時間あたりの上限)

| 送った人 | 上限 |
|---|---|
| ログイン済みのゲスト | 1 人 5 件 |
| ログイン前の人 | 接続元ごとに 3 件、かつログイン前の全体で 30 件 |

全体の 30 件に達すると、ログイン前の人は 24 時間ほど誰も送れなくなります(ログイン済みのゲストは送れます)。

## 戻すとき

```sql
drop table if exists public.contact_messages;
drop function if exists private.guard_contact_messages();
```
