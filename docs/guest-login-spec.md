# ログインの仕様(ゲスト ID 方式)

公開サイトに入るためのログインの仕様です。サイト全体の仕組みは [site-overview.md](site-overview.md) を見てください。

> **状態(2026-11-09)**: この仕様はブランチ `feat/20261108-guest-id-login` で作られ、開発用 Supabase で試し済みです。`main` にはまだ入っていません。本番への反映手順は、そのブランチの `docs/guest-id-login-prod-runbook.md` にあります。反映が終わるまで、本番は「メールアドレスとパスワード」だけのログインです。

## 1. オーナーとゲストの違い

| 項目 | オーナー | ゲスト |
|------|----------|--------|
| ログインに使うもの | メールアドレス + 自分のパスワード | オーナーが発行した ID + 共通パスワード |
| ID の形 | メールアドレス | 英小文字と数字 12 文字(例の形: `k7m2xq9pa4tz`) |
| 期限 | なし | 発行から 30 日 |
| 入れるページ | すべて(`/admin`・`/styleguide` を含む) | トップと作品詳細だけ |
| 見える作品 | 非公開も含めてすべて | 公開中の作品だけ |

- ID に使う文字は、見間違えやすい `0` `o` `1` `l` `i` を除いた英小文字と数字です。
- 期限のない閲覧者(以前からのメールアドレス型のゲスト)も、そのまま残せます。名簿の期限の欄が空(NULL)なら無期限です。

## 2. ログインの流れ(3 つの関門)

ログイン欄は 1 つで、オーナーもゲストも同じ欄に入力します。

| 関門 | どこで | 何をするか |
|------|--------|------------|
| ① 入力の変換 | 画面(`lib/guestId.ts` の `toLoginEmail`) | `@` を含まない入力は `ID@guest.invalid` に変換する。全角は半角に、大文字は小文字にそろえる。`@` を含む入力(オーナーのメールアドレス)はそのまま使う |
| ② ログインの許可証を出すか | Supabase の認証(Hook `public.guest_access_token_hook`) | 期限切れのゲストには許可証(トークン)を出さない。オーナーは対象外 |
| ③ データを渡すか | データベースの RLS(`private.is_reader()`) | 期限切れの行は閲覧者として数えない |

- `guest.invalid` は、実在しないことが規格(RFC 2606)で決まっているドメインです。ゲスト用のメールが誰かに届くことはありません。
- ②の Hook は、ログインのたびと、許可証の更新(約 1 時間ごと)のたびに呼ばれます。
- ②に不具合が起きたときは、ログインを止めずに素通しします(オーナーが締め出されないため)。その場合も③がデータを守ります。
- 期限切れの人には「閲覧期限が切れています。下の「ログインできないときのお問い合わせ」からご連絡ください。」と表示します。
- 名簿 `private.readers` に `expires_at`(期限の日時)の欄を足しています。

ファイル(ブランチ `feat/20261108-guest-id-login` 上): `supabase/migrations/20261108120000_guest_id_expiry.sql`、`lib/guestId.ts`、`components/AuthGate.tsx`

## 3. ゲスト ID の発行と管理

管理画面 `/admin/guests`(メニュー名「ゲストID」)で行います。オーナーだけが使えます。

| 操作 | ボタン | 何が起きるか |
|------|--------|--------------|
| 発行 | 「ゲストIDを発行」 | 新しい ID を 1 つ作り、期限(30 日後)と一緒に表示する |
| 一覧 | — | 発行済みの ID・発行日・期限・状態(有効 / 期限切れ / 無期限)を表示する |
| 停止 | 「今すぐ止める」→「本当に止める」 | その ID の期限を今にする。次のログインから入れない |
| 共通パスワードの反映 | 「共通パスワードを反映」→「本当に再設定する」 | 期限内のゲスト ID 全員に、今の共通パスワードを設定し直す。結果は「更新 n 件 / 失敗 n 件」で出る |

- 発行と反映の処理は、Supabase 上の小さなプログラム(Edge Function `guest-admin`)が行います。
- この処理には、すべての操作ができる強い鍵(service role キー)が要ります。鍵は Supabase のサーバー側にだけ置き、画面やリポジトリには出しません。
- `guest-admin` は、呼んだ人がオーナーかどうかを毎回確かめてから動きます。
- 期限が切れた ID も記録として一覧に残ります。

ファイル(同ブランチ上): `supabase/functions/guest-admin/index.ts`、`app/admin/guests/GuestsSection.tsx`

## 4. ゲストへの案内

ゲストには次の 3 つを伝えます。

| 伝えるもの | 内容 |
|------------|------|
| サイトの URL | https://tommyu130403.github.io/portfolio/ |
| ID | 発行した 12 文字 |
| パスワード | 共通パスワード |

- **ID とパスワードは別の手段で送ります**(例: ID はメール、パスワードはチャット)。片方が漏れても入れないようにするためです。
- 期限は発行から 30 日です。延ばすときは新しい ID を発行します。

## 5. パスワードの管理

| もの | 保管場所 | 見直せるか |
|------|----------|------------|
| 共通パスワード | Edge Function の秘密の設定 `GUEST_SHARED_PASSWORD` と、オーナーのパスワード管理アプリ | Supabase の画面では後から値を見られない。パスワード管理アプリで見る |

- 共通パスワードは、チャット・Git・普通のメモアプリに残しません。
- パスワードを忘れたときの再設定の仕組みはありません。ゲストの ID は実在しないメールアドレスなので、再設定のメールも届きません。
- 共通パスワードを変えるときは、秘密の設定を新しい値にしてから、管理画面の「共通パスワードを反映」を押します。

## 6. 残るリスク(許容済み)

- 期限が切れても、すでに表示した画像の URL は最大 60 分使えます。
- ログイン中に期限を迎えた人は、最大約 1 時間(次の許可証の更新まで)、中身が空のページを見ることがあります。
- 一度ゲストになった人は、共通パスワードを知ったままです。安全を支えるのは「ID を推測されにくいこと(12 文字)」と「30 日の期限」の 2 つです。
