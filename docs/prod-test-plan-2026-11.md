# 第三者公開に向けた本番運用テスト計画(2026-11-10)

ポートフォリオサイトを採用担当など第三者に見せる前に、何を・どの順で・誰が・どう合否判定するかを決めた計画書です。この文書は計画だけを扱い、テストの実施と見つかった問題の修正は別の依頼で行います。

- 読み手: オーナー本人(エンジニアでなくても読める書き方にしています)
- 確認時点: 2026-11-10 の `main`(PR #224 まで)と公開サイト
- 仕組みの説明は [site-overview.md](site-overview.md) を正とします

## 1. 範囲と前提

### 1-1. このテストで守りたいこと

| 順位 | 守りたいこと | 破れたときに起きること |
|---|---|---|
| 1 | 見せてはいけないものが見えない | 非公開の作品・守秘情報・鍵が外に出る。取り返しがつかない |
| 2 | 見せたいものが壊れずに見える | 採用担当が途中で読むのをやめる。評価の機会を失う |
| 3 | 壊れたときに気づけて、戻せる | 壊れたまま何日も公開が続く |

### 1-2. 前提(観測済み)

## 3. テスト項目

「いつ」の意味: 公開前 = 公開前に 1 回、毎回 = 公開サイトを作り直すたび(PR をマージするたび)、定期 = §5 の周期。合格の基準が「決め終えている」「記録されている」の項目は、判断や記録が済んだことをもって合格とします。

## 4. 公開可否の判定

### 4-1. 実施の順序

| 段階 | 内容 | 進む条件 |
|---|---|---|
| 0 | オーナーの判断を先に済ませる: L2(検索)、B2(公開リポジトリの下書き)、I6(問い合わせの確認周期) | 3 点が決まっている |
| 1 | A・B(見せてはいけないものの確認) | 全項目が合格 |
| 2 | E(掲載内容)と G4(文章の読みやすさ) | 必須項目が合格 |
| 3 | C・D・G・H・I・J(動作と使い勝手) | 必須項目が合格 |
| 4 | F(速さ) | 結果が記録されている |
| 5 | K(運用の稽古)と L | 必須項目が合格 |
| 6 | 判定 | 4-2 の基準 |

段階 1 で不合格が出たら、段階 2 以降に進まずに修正を先に行います。修正のあとは、その項目と、同じ領域の必須項目をやり直します。

### 4-2. 判定の基準

| 判定 | 条件 |
|---|---|
| 公開してよい | 必須の項目がすべて合格。推奨の不合格は一覧になっていて、オーナーが 1 件ずつ「このまま公開 / 直してから公開」を決めている |
| 公開しない | 必須の項目に不合格または未実施が 1 件でもある |
| 公開後すぐ止める | 公開後に A・B の不合格が見つかった(§5-2 の「漏えいの疑い」の手順へ) |

### 4-3. 結果の残し方

実施のたびに、項目 ID・日付・実施者・合否・証拠(画面の写し、実行結果)を 1 つの文書(`docs/prod-test-result-<日付>.md`)に残します。確かめていない項目は「未実施」と書き、合格として扱いません。
