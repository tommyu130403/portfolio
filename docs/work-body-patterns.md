## 新しい図版の記法（v2 レイアウト向け）

作品詳細の新レイアウト（v2）の図版として足した記法。どれも `::: 名前` 〜 `:::` の 1 ブロックで、`::: figure` / `::: card` / `::: grid` の中にも置ける。v1（公開中の見た目）でも崩れず、枠線で区切った素朴な見た目で出る（旧い見た目が無いので、v1 専用の凝った表現はしない）。使う場面は下の表で決める。

| 記法 | 使う場面 | 置き方 |
|---|---|---|
| `::: team` | 体制・役割の人数を見せる | 作品の「関係者」データから描く。本文に人数は書かない |
| `::: schedule` | 計画と実際の日程のずれ | 年表。日付が 2 つ以上のとき |
| `::: flow ラベル numbered` | 順序のある進め方の地図 | 矢印なし・番号つき。P3 の flow は従来どおり |
| `::: stairs` | 積み上げる段階（到達したい状態） | 1 行 1 段、右へずれていく |
| `::: summary` | 作品の要約（リード・課題 / 打ち手 / 結果） | 作品の先頭セクションに 1 つ |
| `::: merge` | 複数の流れを 1 本に統合した | 元の流れ → 統合後の手順 |
| `::: triage` | 入れた・削った・見送った | 範囲決めの図 |
| `::: related` | つながる作品 | 作品の最後のセクションに 1 つ |

共通の決まり:

- `:` は全角 `：`、`|` は全角 `｜` でもよい。空行は自由。
- 開き行に見出しがあると、その図は自分の枠を持つ（`::: figure` の中・見出しなしのときは枠なし）。見出しは `見出し | 補足文`。
- 中身が読めない・空のときは何も出ない（`:::` の文字は出ない）。
- 閉じ `:::` を書き忘れても、次の本文を飲み込まない（図の行の形でない最初の行で終わる）。
- **`::: summary` / `::: related` は既存のセクションの中に書く**（summary は最初のセクションの先頭、related は最後のセクションの末尾）。専用の見出し（`# …`）を立てない。新レイアウトではブロックが別の場所へ移るため、見出しだけが中身なしで残ってしまう。
- 狭い幅（本文の幅 390px など）でも横スクロールしない。各記法の切り替わりの幅は下に書く。

### team（体制のドット図）

```
::: team 体制と、自分が兼ねた 4 つの役割
- 意思決定・進行 = Product, Project
- デザイン = Designer
:::
```

- v2 の作品詳細は、期間・役割をヒーローの「事実」の列に並べる（ヒーローは全幅で 1 列: 画像が上、文字が下）。体制は本文の `::: team` で見せ、人数の合計（計 N 名）もその図の見出し行に出る（実人数。自分は複数の役割を兼ねても 1 人と数えるので、兼務があるとドットの数より少なく、そのときは合計の横に「（自分は 1 名で計上）」と出る）。
- 必ず閉じ `:::` で終える（閉じ忘れても後ろの普通の箇条書きは飲み込まないが、行の形が合う行までは中身として読む）。
- データは `works.stakeholders`（関係者）と `works.stakeholder_breakdown`（役割ごとの人数）。ドットは人数ぶん（1 役割に 11 個以上は 10 個＋`+N`）。自分（`me`）の役割は先頭の 1 つが primary 色。
- `- 表示名 = 層名, 層名` は、その層を 1 つのグループにまとめて「表示名」で出す。層名は大文字小文字・前後の空白を無視して照合し、書いた順に並べる。存在しない層名は無視する。
- **どの行にも書かなかった層は、最後に層名のままのグループで足される**（落ちない）。行を 1 本も書かなければ、層ごとに 1 グループ。
- 人数は 内訳（役割名の一致）→ カードのメモ「N名」→ 1 名 の順。組織カード（`org`）は数えない。
- 見出しを省くと「体制」。関係者データが無い作品では何も出ない。スタイルガイドなど作品の行が無い場所では見本の枠が出る。

### schedule（計画と実際の年表）

```
::: schedule 計画と実際のリリース(記法の見本。実在の作品の日程ではない) | 学生側は計画どおり、企業側は約 2 か月遅れた
range: 2021-05 .. 2021-11
lane: 学生側(toC)
- plan: 2021-05-17 .. 2021-09-01
- actual: 2021-08-01 .. 2021-09-01 | 実際 8月
- 2021-05-17 | 仕様すり合わせ
lane: 企業側(toB)
- plan: 2021-06-14 .. 2021-09-01
- delay: 2021-09-01 .. 2021-11-01 | 約 2 か月遅れ
- actual: 2021-11-01 .. 2021-12-01 | 実際 11月
- 2021-06-14 | 仕様すり合わせ
:::
```

- 日付は `2021-05-17`（年-月-日）か `2021-05`（その月の 1 日）。実在しない日付の行は捨てる。
- `range: A .. B` は月の範囲（A の月の 1 日から B の月の末日まで）。**省略すると、すべての日付の最小〜最大を月で切り上げて決める**。範囲の外の日付は端（0〜100%）に寄せる。
- `lane:` より前の行は名前なしの 1 レーン。レーンごとに計画（`plan`）は 1 本、実際（`actual`）と遅れ（`delay`）は何本でも、節目は `- 日付 | ラベル`。`| ラベル` は省略できる。
- 節目のラベルには日付が自動で付く。日付は厳密な日を出さず、おおまかな表記にする（1〜10 日 = `M月初旬`、11〜20 日 = `M月中旬`、21 日〜 = `M月下旬`、月の最終日 = `M月末`。2026-11-18 オーナー判断）。期間も同じ表記（例: `5月中旬 – 8月末`。月の 1 日から翌月 1 日までは `N月`）。ラベルにすでに `7月末`・`8月上旬` や `7/30` のような形があれば付かない。本文のラベルにも厳密な日付（`10/10` など）は書かない。
- 幅 640px 以上は軸つきのチャート（計画=グレーの棒・実際=ミントの棒・遅れ=赤の破線・節目=丸）。640px 未満はチャートを出さず、レーンごとの縦の一覧（日付順）になる。スクリーンリーダーは一覧を読む。
- `legend:` 行は受け付けるが使わない。凡例（計画 / 実際）は、計画の棒がどこかにあるときだけ出る。
- `- span: 開始 .. 終了` は中立の帯（計画の棒と同じグレー・同じ高さ）。計画ではないので凡例には出ない。レーンは `span` か `actual`（ミント）を 1 本だけ書き、その上に節目の丸を載せられる。`span` は 1 レーンに 1 本（2 本目は無視）。
- 工程を並べるときは、工程ごとに lane を作らず、レーンを 2 本ほどに絞る（894c の見た目）: 自分が R / A の工程を `lane: 自分が担当した工程`（`- actual: 最初の開始 .. 最後の終了`、ミント）、C / I だけの工程を `lane: 関わった工程`（`- span: …`、グレー）にまとめ、工程ごとに開始日の節目 `- 開始日 | 工程名` を 1 つ置く（ラベルは「工程名 M月初旬」などになる）。節目の近く（10 日未満）に実日付の節目があれば、実日付だけ残して工程名を合流させる（例: `要件すり合わせ・キックオフ`）。計画と実際の凡例は出ない。縦の一覧では、`span` / `actual` の期間の行は、計画の棒が図に無いとき「実際」「期間」などの語を付けずに期間だけを出す。
- v2 ではヒーローの「期間」からタイムラインは開かない。工程の見せ方は本文の `::: schedule` に書く。

### flow numbered（番号つきステップ）

```
::: flow 進め方 numbered
- プロジェクト憲章で合意
- 体制・投資の提案
- リサーチ
:::
```

- `numbered` は単独の語として開き行に書く（ラベルには出ない）。矢印なし・番号つきで、幅に応じて折り返す。`highlight=` は効かない。`numbered` を付けない flow は従来どおり。

### stairs（階段）

```
::: stairs
- 適性検査 | 客観 | 定量的に自分の特性を理解している | 受験は 1 回
- ガクチカ | 分析 | 力を入れたことを具体的に書けている | 500 字 × 最大 3 | mid
- 自己PR | アウトプット | 結論と根拠で 300〜400 字にまとまる | 500 字 × 1 | accent
:::
```

- 必ず閉じ `:::` で終える。
- 行は `名前 | タグ | 説明 | 右端の注記 | tone`。tone は省略（中立）か `mid`（途中）か `accent`（到達点。**1 図に 1 行**）。
- 幅 560px 以上は 1 行ずつ、上から 4% ずつ右へずれる（上限 24%）。560px 未満はずらさず、名前とタグ → 説明 → 注記の順に積む。

### summary（要約）

```
::: summary
lead: 作品を 1〜2 文で言い表す
problem: 課題
action: 打ち手
result: 結果
:::
```

- 各項目は 1 行・省略できる。**v1 では書いた場所に出る**（リード → 課題 → 打ち手 → 結果の 3 枚）。
- **v2 では `lead` だけをタイトルの下（ヒーロー）へ移し、本文のこの場所には繰り返さない**（最初の最上位の 1 つだけ。`::: figure` / `card` / `grid` の中・2 つ目以降は動かない）。課題・打ち手・結果の 3 枚は書いた場所（プロジェクト概要の先頭）に出る。本文幅 760px 以上は横に 3 枚、未満は縦に積む。古い `release:` の行が残っていても読み捨てる（表示しない）。番号は位置で固定（打ち手が無ければ 01 → 03）。

### merge（統合の流れ）

```
::: merge スカウト型のドメイン・DB を土台に統合
from: Before: エージェント | 流入 › 登録フォーム 2 段 › 判定 › 面談予約 | サイト・フォーム・保存先が別
from: Before: スカウト | 流入 › 会員登録 › プロフィール入力 | 入口が重複
into: After: 1 本の導線
- STEP1 | 登録情報
- 通過者のみ | 面談予約 | dashed
- STEP3 | 会員登録・認証 | accent | ここで初めて認証
:::
```

- `from:` は `題 | 本文 | 注記` の枠（横に並ぶ。560px 未満は縦）。開き行の文は矢印の横の説明。
- `- タグ | 名前 | tone | 注記`: tone は `accent`（強調の線）か `dashed`（点線・条件つきの手順）、省略可。注記は手順の下に出る。手順が 1 つも無ければ何も出ない。
- `note:` は図の下の補足の 1 行。

### triage（入れた・削った・見送った）

```
::: triage
in: 入れた
- 強みを「アピールポイント」として項目化
cut: 削った | 希望業種・職種は目的から逆行するため
- 希望業種
- 希望職種
defer: 見送った
- 候補者リスト
note: 見送った項目は次の期に再検討
:::
```

- `in:` / `cut:` / `defer:` の下の `- ` が項目。`ラベル | 理由` でラベルを変え、理由を添えられる（省略時は 入れた / 削った / 見送った）。並びは常に 入れた → 削った → 見送った。項目の無い見出しは出ない。
- 削った項目は取り消し線のチップ（`<del>`）。幅 200px ぶんで折り返し、狭ければ縦に積む。


- 必ず閉じ `:::` で終える。
- `- 作品の ID | ラベル [| accent]`。文字だけのカードで、ラベルの下に作品名が出る。公開中でない・存在しない ID は飛ばし、全部飛ばすと何も出ない。見出しを省くと「この作品とつながる作品」。
- **v2 では本文から取り除き、ページの末尾（最後のセクションの下・上に罫線）へ移す**。v1 は書いた場所に出る。P11 の `::: workcard`（サムネイル付き 1 枚）とは用途が違う。

### bars は v2 で線描き

`::: bars` の棒は、v2 では塗らず線だけで描く（増加 = ミントの枠線、減少 = 赤の破線、変化なし = 薄い枠線）。値の文字色は変わらない。v1 は従来どおり塗る。

### v2 での要約・関連の移動

`::: summary` と `::: related` を v2 でページの上下へ移すのは、公開ページと admin のプレビューの両方（`WorkDetailView`）。セクションの個数と順序は変えない（編集ボタンの番号・目次が使うため）。移したあと見出しも本文も空になったセクションは何も描かない。

## 色と線の決まり

作品の図版（`::: figure` の枠・`::: card`・`::: flow`・`::: beforeafter`）の色と線は、v2 レイアウトでは次の決まりに従う。正は `lib/work-figure-tone.ts` の `WORK_FIGURE_TONE`。スタイルガイドの「作品図版の色と線」で見本を確認できる。

| キー | 意味 |
|---|---|
| 枠（frame） | 図版の外枠。線だけで塗らない |
| セル（cell） | 図版の中の面（ステップ・カードの既定） |
| 強調（accent） | 強調は線と文字だけ。面は塗らない |
| 順序の目印（stepMark） | ステップの順序を示す上線 |
| データの印（dotSelf / dotOther / barPlan / barActual） | 自分・ほかの点、計画・実績の棒 |
| つまずき・遅れ（blocked） | 破線と文字だけで示す。塗らない |
| 見送り（deferred） | 破線 |
| 削った項目（cut） | 打ち消し線 |

禁止: ミントの広い塗り、danger（赤系）の塗り。

## レイアウトの切替（v1 / v2）

- 切替の定数は `lib/work-detail-layout.ts` の `WORK_DETAIL_LAYOUT`（"v1" か "v2"）。
- 1 回の確認だけなら、URL に `?layout=v1` または `?layout=v2` を付ける（例: `/works?id=…&layout=v2`）。定数は変わらない。
- 定数を書き換えて全員の表示を切り替えるには、PR のマージとデプロイが必要。
- v1 のクラス名は凍結。直すのは v2 だけ（各コンポーネントの `v1` / `v2` のクラス表に `// v1 は凍結: 直すのは v2 だけ` と書いてある）。
