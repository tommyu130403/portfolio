# プロジェクト概要

中級のプロダクトデザイナーに向けて、OOUI(オブジェクト指向UI)を実務で使えるようにする社内勉強会を企画し、教材一式を設計した。1回60分×全6回と事前課題で構成し、講義と演習の比率はおよそ3:7である。共通題材には実在サービスのAmazonを使う。2026年10月に設計を始め、現在も進行中である。

# 背景と課題

## 背景

対象は、OOUIの概念は知っているが実務で使えていない中級デザイナーである。画面が増え続ける、モーダルが深くなる、エンジニアとデータ構造の話が噛み合わない、といった悩みを想定した。社内の情報設計研修資料も参考にしたが、丸写しせず取捨選択した。

## 目的

1. OOUIの価値を判断できる
2. 設計手順を実践できる
3. 既存UIを評価・改善できる
4. 使い分けを判断し、エンジニアに渡せる

## ゴール

成果は「理解した」ではなく「自分の担当プロダクトで手順を回せる」とした。

- 事前・事後アンケート(同一8問)の差分平均 +1.0以上
- 最終回の成果物を「起票した/予定がある」とした比率 5割以上
- 各回の理解度確認の正答率 8割以上
- 欠席者が「問題なく合流できた」比率 8割以上

最終回の1か月後にも、同じ設問で追跡する。

## やらないこと

- 架空のサービスは使わない
- サービスの優劣は論じず、構造の指摘に限る
- スクリーンショットを教材に貼らない
- 満点を次回参加の条件にしない

### 積み上げ式のカリキュラム

回1は実在サービスのアンチパターンで「なぜOOUIか」を動機づける。回2・3でオブジェクトを抽出し、回4でビューを設計する。回5で使い分けと実装接続を扱い、回6で自分のプロダクトを13項目のチェックリストで評価・改善する。

### 人数の変動と欠席への備え

参加人数は開始まで確定しない。そこで、ワークは全回とも個人作業にした。9名以上のときは、共有をSlackへの投稿と2〜3名の指名に切り替える。欠席者には30〜40分のキャッチアップパックを用意した。

### 設計判断の見直し

| 変更前 | 変更後 |
| --- | --- |
| 架空サービスの要件文を読ませる | 実物を開いて読み取る |
| 全5回 | 全6回(外部の調査資料を取り込んだ) |
| スライドを配布 | 各回の要点ページ 1 枚を配る |
| 履修の判定は「全問正解」 | 「提出した時点で完了」 |

### 教材の運用

教材はMarkdownを正とし、運営用と参加者用のHTMLを変換スクリプトで生成する。講師向けの見出しは自動で除外される。
