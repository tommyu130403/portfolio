# プロジェクト概要
::: summary
lead: 中級のプロダクトデザイナーに向けて、OOUI(オブジェクト指向UI)を実務で使えるようにする社内勉強会を企画し、教材一式を設計した。
problem: OOUIの概念は知っているが、実務で使えていない中級デザイナーがいる。
action: 1回60分×全6回と事前課題で構成し、Amazonを共通題材に教材一式を設計した。
result: 実施済みの回では、参加者の7割程度から自身の現場プロダクトに活かせそうとの所感を得た。
:::

1回60分×全6回と事前課題で構成し、講義と演習の比率はおよそ3:7である。共通題材には実在サービスのAmazonを使う。2026年10月に設計を始め、2026年11月時点で実施中である。

# 役割
プランナーとして、企画、教材設計、運営・実施を1人で担当した。

::: team 体制 | 企画から実施までを 1 人で担当
- 企画・教材設計・運営 = Project
:::

# 背景と課題
対象は、OOUIの概念は知っているが実務で使えていない中級デザイナーである。画面が増え続ける、モーダルが深くなる、エンジニアとデータ構造の話が噛み合わない、といった悩みを想定した。社内の情報設計研修資料も参考にしたが、丸写しせず取捨選択した。

::: grid cols=2 gap=4
::: card 目的
1. OOUIの価値を判断できる
2. 設計手順を実践できる
3. 既存UIを評価・改善できる
4. 使い分けを判断し、エンジニアに渡せる
:::
---
::: card ゴール
到達点は「理解した」ではなく「自分の担当プロダクトで手順を回せる」とした。
:::
:::

| 指標 | 基準 |
| --- | --- |
| 事前・事後アンケート(同一8問)の差分平均 | +1.0以上 |
| 最終回の成果物を「起票した/予定がある」とした比率 | 5割以上 |
| 各回の理解度テストの正答率 | 8割以上 |
| 欠席者が「問題なく合流できた」比率 | 8割以上 |
::: caption 最終回の1か月後にも、同じ設問で追跡する。

### 人数の変動と欠席への備え

参加人数は開始まで確定しなかった。人数がどう転んでも回るよう、次のように備えた。

::: figure 人数と欠席への備え
| 状況 | 備え |
| --- | --- |
| 参加人数が開始まで確定しない | ワークは全回とも個人作業にした |
| 9名以上のとき | 共有をSlackへの投稿と2〜3名の指名に切り替える |
| 欠席したとき | キャッチアップ資料(30〜40分の資料と動画)を配布した |
:::
