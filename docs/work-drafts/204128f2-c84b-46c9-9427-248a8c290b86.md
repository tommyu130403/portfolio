# プロジェクト概要

キャリアチケット転職で、転職エージェントサービスとスカウト型転職サービスの登録導線を一本にまとめた。
転職エージェントサービスの既存登録フォームを廃止し、スカウト型転職サービスのドメインとデータベースを土台に新しい登録導線を設計しリリースした。

# 役割

自身はリードデザイナーとして要件整理とUX・UI設計のレビューを担い、品質に関わる判断をした。実際のデザインはメンバーが担当した。

# 背景と課題

## 背景

- スカウト型転職サービスの収益化が、想定より遅れていた。
- 転職エージェントサービスも同じ時期に立ち上げフェーズにあり、リソースが分散していた。
- 今後、ブランド全体はエージェントを主軸とするサービスになる方針だった。

## 目的とゴール

::: grid cols=2 gap=4
::: card 目的
登録導線を一本化し、広告費をかけずにスカウト型サービスの登録者データベースを蓄積する。あわせて、両サービスの登録者を最大化する。
:::
---
::: card ゴール
- 新しい登録導線を期日(9月30日目標)までにリリースする。チームのミッションも「期日内にリリースすること」とした。
- 転職エージェントサービスのコンバージョン率と面談設定数を落とさない。
- その上で、スカウト型サービスにも登録される状態をつくる。スカウト側の登録者数のために、他を犠牲にする必要はないとした。
- できるだけ工数をかけずに実現する。
:::
:::

## 課題

- ブランドの転職トップページは、記載がすべてスカウトに関する内容だった。サービスを誤認されるおそれがあった。企業ロゴの掲載も、実際より多くのスカウトが届く印象を与えるおそれがあった。
- スカウト営業は大きく縮小する方針だった。訴求内容と、実際にスカウトが届く体験との期待値をそろえる必要があった。
- 登録の途中で認証を挟むと、離脱するリスクがあった。
- 途中離脱した人の重複登録や、他人のメールアドレスを入力されるケースへの対策が必要だった。

## スコープ外

- 判定条件に応じたカレンダー表示の出し分け
- LINE連携
- 既存ユーザーデータの新データベースへの移行
- メールアドレス誤入力時の修正導線
- 退会・メールアドレス変更オペレーションの見直し

## 要件整理

2サービスの登録フォームを対比表にまとめ、1本の導線に必要な項目と規則を決めた。

::: figure 要件整理
| フォーム項目 | 両サービスの登録項目を対比し、重複をまとめて統合した |
| 選択肢 | 職種・業界・年収の選択肢も対比し、エージェント基準で統合した |
| 再開URL | 有効期限を24時間に統一した |
| 同一判定 | 同一ユーザーの判定はメールアドレスで行う |
| 既存ユーザー | 過去の登録者のため、スカウト型サービス側のエージェント登録導線は残した |
:::

# 成果

## チームの成果

- 目標期日の前日、2025年9月29日に本番リリースした。
- メインフロー、新着スカウト0件時の画面、年収選択肢の変更箇所、「よくある質問」のデザインを確定させた。
- リリース後、新しい導線からスカウト型サービスの登録まで進むユーザーが現れた。
- エージェント側のコンバージョン率・面談設定数に、リリース後の大きな低下は見られなかった。リリース前後で計測の定義が異なるため、厳密な比較はしておらず、数値も載せていない。

## 自分の貢献

要件整理とUX・UI設計のレビューを担い、統合後の導線の体験と画面の品質を担保した。
