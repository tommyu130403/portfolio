# プロジェクト概要
::: summary
lead: 2021年6月、キャリアチケットスカウトの立ち上げにあたり、Figmaとコードの部品管理の仕組みをエンジニアと設計した。
problem: デザインと実装を同時に進める中、部品のスタイル変更が別の画面を崩したり、定義にない色が使われたりするおそれがあった。
action: デザインとコードの部品の層をそろえ、スタイルを部品ごとに閉じる構成をつくった。
result: 部品98件・画面56件を、スタイルが他に漏れない構成で立ち上げ期のリリースに間に合わせた。
:::

# 役割と体制
デザイナー兼フロント開発の担当として、Figmaのライブラリ構成と色・部品の定義を担った。コードの層構造とCSSの管理方針は、エンジニアと一緒に決めた。

::: team 体制
- デザイン = Designer
- 開発 = Engineer
:::

# 背景と課題
キャリアチケットスカウトの立ち上げでは、デザインと画面の実装を同時に進める必要があった。画面と部品が増えるほど、ある部品のスタイル変更が別の画面を崩したり、デザインで定義にない色が使われたりするおそれがあった。そこで、Figmaとコードで部品の層をそろえ、スタイルの効く範囲を部品ごとに閉じることにした。

## デザインシステム
Figmaでの運用ルールを設計し、カラーの定義やコンポーネントの構成を検討した。基本構造としてAtomic Designを採用した。

::: figure Atomic Design の 5 段階 | Brad Frost が 2013 年に提唱し、2016 年に書籍化。UI を化学のメタファーで 5 段階に分ける
| 段階 | 中身 |
| --- | --- |
| Atoms | ボタン、入力欄、ラベルなど、これ以上分解できない最小要素 |
| Molecules | 検索フォーム(ラベル+入力+ボタン)のような小さな組み合わせ |
| Organisms | ヘッダーや候補者一覧カードなど、意味のあるまとまり |
| Templates | データを入れる前のページの骨組み |
| Pages | 実データが入った最終画面 |
::: caption Frost 自身は、これを厳密なフォルダ分類ではなく、部品と全体を行き来して考えるための考え方だと説明している。
:::

| Biz / Con Master | 実際の画面ファイル |

:::

## コンポーネントの層

::: figure コードの層の定義 | Atomic Designの考え方を、実装上の置き場所と命名に落とした

| 層 | 例と置き場所 |
| --- | --- |
| foundation(トークン) | 色・寸法・画面幅・型 — styles/foundation |
| Parts | Button, Checkbox, Modal — components/Parts |
| Projects | Header, Footer, {purpose}Dialog — components/Projects |
| Template | ページの骨組み — components/Template |
| Pages | 実データの入った画面 — pages/{page}.tsx |

:::

## CSSモジュール設計

CSSモジュール(クラス名に自動で固有の目印が付き、そのファイルを読み込んだ部品にしか効かない仕組み)を、次の目的で導入した。

::: figure CSSモジュールを入れた目的
::: grid cols=3 gap=4
::: card 1. 部品ごとに閉じる
部品ごとにスタイルを閉じ込め、他の部品や画面に影響させない
:::
---
::: card 2. 共通ルールを配る
デザインの共通ルール(色・文字・余白・画面幅)はSass(変数や共通の型を使ってCSSを書く言語)で全ファイルに配る
:::
---
::: card 3. 全体は 1 か所だけ
全体に効かせるスタイルは「土台」の1か所だけにする
:::
:::
:::

::: figure CSSモジュールの構成 | 全体に効くのはglobalsの1か所、共通ルールはfoundationから配り、部品と画面はmodule.scssに閉じる

# 成果
::: grid cols=3 gap=4
::: card tone=accent 立ち上げに間に合わせた
部品98件は部品と1対1、画面56件は画面ごとにスタイルを分けて管理する構成にし、立ち上げ期のリリースに間に合わせた
:::
---
::: card 既存の画面を崩さない
スタイルが部品の外へ漏れない構成にしたため、画面を足すときに既存の画面を崩す心配をせずに作れるようになった
:::
---
::: card 色の誤用を防ぐ
色はコントラスト基準(WCAG AA)を満たす組み合わせだけを指定できるようにし、デザイン時の色の誤用を防ぐ仕組みにした
:::
:::
