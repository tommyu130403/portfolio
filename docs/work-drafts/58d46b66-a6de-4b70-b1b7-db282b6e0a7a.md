# 取り組み

## デザインシステム
figmaでの運用を設計。
カラーの定義やコンポーネントの構成を検討した。基本構造としてAtomic Designを採用した。

> **Atomic Design（Brad Frost, 2013年提唱・2016年書籍化）**
>UIを化学のメタファーで5段階に分けている。Atoms（ボタン、入力欄、ラベルなどこれ以上分解できない最小要素）、Molecules（検索フォーム＝ラベル＋入力＋ボタンのような小さな組み合わせ）、Organisms（ヘッダーや候補者一覧カードなど、意味のあるまとまり）、Templates（データを入れる前のページの骨組み）、Pages（実データが入った最終画面）です。Frost自身は、これは厳密なフォルダ分類ではなく「部品から全体へ、全体から部品へ行き来して考えるためのメンタルモデル」だと述べた。

## CSSモジュール設計

CSSモジュール(クラス名に自動で固有の目印が付き、そのファイルを読み込んだ部品にしか効かない仕組み)を、次の目的で導入した。

1. 部品ごとにスタイルを閉じ込め、他の部品や画面に影響させない
2. デザインの共通ルール(色・文字・余白・画面幅)は Sass で全ファイルに配る
3. 全体に効かせるスタイルは「土台」の1か所だけにする

最終的な設計として以下の管理方針と構造となった。

* 閉じ込める:部品も画面も `.module.scss` にし、スタイルの漏れを仕組みで防ぐ。
* 共有する:色・文字・画面幅はSassの変数と型で全ファイルに同じものを配る。
* 全体は1か所:グローバルなスタイルはリセットと基本設定だけ。
* 調整は外から:部品の状態はクラスの付け外しで切り替え、配置は親が`className`で調整する。

```
■スタイル構造

styles
├── globals.scss                 # A 全体に効く唯一の入口(_app.tsx で1回だけ読む)
├── foundation                   # B デザインの共通ルール(CSSは出力しない定義集)
│   ├── _ress.scss               #   ブラウザ差をならすリセット
│   ├── _base.scss               #   html / body / a / img / フォント
│   ├── _variables.scss          #   色・レイアウト寸法・アイコン一覧
│   └── _mixin.scss              #   画面幅の切替・文字サイズ・影・カード等の型
└── pages                        # C 画面専用スタイル(56件)
    └── [画面名]_[状態].module.scss   #   例: event_detail / chat_edit

components/[階層]/[部品名]
├── index.tsx                    # D 部品本体
└── index.module.scss            #   部品専用スタイル(98件、部品と1対1)
```
