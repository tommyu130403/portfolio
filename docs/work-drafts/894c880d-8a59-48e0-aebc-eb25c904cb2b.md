# プロジェクト概要
::: summary
lead: 自己分析とプロフィール入力を進めると企業からスカウトが届く、新卒向けサービスの初期範囲を決めて、リリースまで率いた。
problem: 人材紹介(カウンセリング)主体では、早期に動く学生に価値を出せず、集められる学生の数に上限があった。
action: キャリアアドバイザーが担ってきた「強みを見つける・軸を固める」支援を、プロフィール入力の機能に置き換えた。
result: β版として決めた機能をすべて実装してリリース。「自己分析ができる」は訴求として足りないとわかり、次の検討につながった。
:::

# 役割と体制
リードデザイナー兼PMとして、プロジェクト憲章の作成、体制と投資の提案、β版の範囲決めを担当した。フロントエンドの実装も自分で行った。

::: team 体制と、自分が兼ねた 4 つの役割
- 意思決定・進行 = Product, Project
- デザイン = Designer

# 背景と課題
これまで支援できていたのは「1000人未満の、認知度の低い企業」で、学生が普通に探していては出会えないセグメントだった。集められる学生の数に上限があり、支援できる範囲を広げる必要があった。

::: figure 事業の狙い | 人材紹介主体からスカウト型へ。どこで詰まり、どこが開くかを同じ 3 段で比べる
::: beforeafter
before: 人材紹介(カウンセリング)主体 → [!早期に動く学生に価値を出せない] → リード獲得が困難
after: キャリアアドバイザーを介さないスカウト型 → [+就活時期を問わずシェアを広げる] → 収益化の機会が増える
:::
:::

## 体制と進め方
デザイナーが自分1人(約1人月)では、計画どおりのリリースに追加で1人月以上が必要と見積もった。必要なスキルと参画時期を整理し、事業責任者に人件費の追加投資を提案した。範囲が曖昧にならないよう、プロジェクト憲章をまとめて関係者と合意した。

## リサーチ
人事・RA(企業の採用を支援する営業担当)の視点を持つ2名とキャリアアドバイザー1名にヒアリングし、学生向けのテストも設計して2021年5月に3名へ実施した。

::: grid cols=3 gap=2
::: card 人事・RA の視点(2名)
一番ほしい学生情報は「基本情報・自己PR・長所短所・写真」。希望条件は途中で変わっても入れ直されないので信用しにくい
:::
---
::: card キャリアアドバイザー(1名)

## β版の範囲
期日までに「まずスカウトができる」状態を出すことを優先し、入れるもの・削るもの・見送るものを分けた。

::: figure β版の範囲決め
::: triage
in: 入れた
- 強みを「アピールポイント」として項目化
- 就活の軸は最大 3 つ・メイン 1 つ
- ガクチカに選択式のカテゴリ
- 適性検査(エゴグラム・受験は 1 回)
cut: 削った | 希望業種・職種は「サービスの目的から逆行する」ため
- 希望業種
- 希望職種
- 企業タイプ
- 高校
- 他社選考状況
- 短所
- 資格
- SNSログイン
defer: 見送った
- 候補者リスト(企業の要望は多かった)
- プッシュ通知(利用状況を根拠に範囲外。部分対応の余地は残した)
:::
:::

::: figure 自己分析の思考フレームと入力ルール | 「客観 → 主観 → 分析 → アウトプット」の順に、到達したい状態を積み上げる。右端はアプリ内の上限
::: stairs
- 適性検査 | 客観 | 定量的に自分の特性を理解している | 受験は 1 回
- 自分史 | 主観 | 今までの行動が洗い出されている | 無制限
- ガクチカ | 分析 | 力を入れたことを具体的に書けている | 300〜500 字 × 最大 3 | mid
- 強み | 分析 | 自分の強みをいくつか言語化できている | 30 字 × 最大 5 | mid
- 就活の軸 | 分析 | 会社・仕事選びの自分なりの基準が明確 | 最大 3・メイン 1 | mid
- 自己PR | アウトプット | 結論と根拠で 300〜400 字にまとまる | 300〜500 字 × 1 | accent
:::
::: caption 自己PRが書けない学生は、自分史の洗い出しから始める分岐にした。
:::

要件フェーズで定義する。ここまでは必ず出す線
:::

::: card MLP
**サービスが魅力的である**
要件フェーズで定義する。日程に応じて調整できる線
:::
