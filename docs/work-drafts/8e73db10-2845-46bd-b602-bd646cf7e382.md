# プロジェクト概要

キャリアチケットスカウトの学生側プロダクト改善として、価値観マッチング機能を企画・仕様化したプロジェクト。既存スカウト機能の課題整理とアイデア出しで方針を決め、仕様に落とし込んだ。

# 役割

- ユーザーヒアリングの設計
- デザイン(外部設計)の検討
- フロントエンド実装

# 背景と課題

## 背景
学生10名・企業5社へのヒアリングから、次の傾向が見えた。
- **自己分析そのものはニーズではない**
- **やりたいことがわからず不安**
- **情報が多すぎて企業探しに疲れ、就活の軸がない**

自己分析機能を拡充するだけでは、良い出会いまでの道のりが長い。知名度のない企業のスカウトは開封すらされない。議論では、スカウトサービスか自己分析サービスか方針を定めるべきこと、競合に対する明確な優位性がないことも挙がった。

::: figure 課題の特定 | ニーズ調査から見えた、ターゲット(早期層〜中間層の 3 セグメント)の共通点
::: grid cols=2 gap=4
::: card 気づき
周囲に就活のやり方を聞きながら自己分析も進めるため、時期の差はあれど「就活の軸・強み」まではたどり着く
:::
---
::: card tone=accent 課題
軸・強みまでは行くが、企業を絞り込める「やりたいこと・将来何がしたいか」の言語化ができない
:::
:::
::: caption 学生の初期接点となるサービスにして集客コストを下げるため、早期層〜中間層をメインターゲットとした。出典: 学生ニーズ表・ポジショニングマップ
:::

## 目的とゴール

::: grid cols=2 gap=4
::: card 目的
学生に「このプロダクトを使えば、自分に合う企業が楽に見つかりそう」と直感的に思ってもらうこと。
:::
---
::: card ゴール
>このプロダクトを使えば、自分に合う企業が楽に見つかりそう

上記目的を達成するために、KGIはオファー承諾率、KPIは学生が興味を持った企業数／登録数とした。

また、承諾率を「開封率×企業への興味関心度」、開封率を「興味を持った企業数÷オファー受信数」と定義することで、目的の達成を測る指標とした。
:::
:::

## 仮説
- 学生の価値観（やりたいこと）が企業と一致していることが、学生の意思決定を変えるフックになる。
- 「自己分析」ではなく「価値観で就活」と訴求すれば、期待値が上がる。

### 方針の検討
適性検査、オフィス見学動画、足跡、記入例の掲載、自己分析のサジェストなどの案が挙がった。その中から、価値観で企業と出会える方向を採用した。

::: figure 「選択式」にした根拠 | 価値観でマッチングするサービス(マッチングアプリ)の比較から得た示唆
::: grid cols=3 gap=4
::: card 人柄が伝わる選択肢
価値観を選ぶと、その人がどういう人かが分かる選択肢を用意する
:::
---
::: card 入力は最小・選択式
アプリの特性上、入力は最低限にし、選択式で価値観を選べるようにする
:::
---
::: card 一致度は見せすぎない
共通点の量を定量的に示す案もあったが、共感度で優劣がつく仕組みは印象バイアスを与えかねないため採用しなかった
:::
:::
::: caption 出典: マッチングアプリの競合分析(価値観重視 × マッチング度の 2 軸)
:::

### 機能設計
- 学生は4つのパラメータから各3項目をチェックボックスで選ぶ。どんなチームで働きたいか、どんな人になりたいか、将来身に付けたいこと、働く上で理想とする環境である。
- 企業は、最も共感したパラメータを1つ選んでオファーを送る。
- 共感度合いで優劣がつく仕組みは、印象バイアスを与えかねないため採用しなかった。

::: figure 学生側の体験 | 4 つの価値観を選ぶと、完了画面で「キャリアに対する考え方」のタイプが分かる
::: flow highlight=0
- 理想のチーム
- なりたい人物像
- 将来身につけたいこと
- 理想とする環境
- 完了(タイプ表示)
:::
:::
