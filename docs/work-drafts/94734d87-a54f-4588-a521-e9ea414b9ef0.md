# プロジェクト概要

キャリアチケットスカウト(以下 CTS)が立ち上げ期(0→1)から拡大期(1→10)へ移るにあたり、市場でCTSが提供すべき価値(ポジション)を明確にするプロジェクトを進めた。

::: flow 当初の 4 段階計画 highlight=4
- 現状の可視化
- 仮説・考察
- インサイト・課題定義
- 提供価値と理想状態の定義
:::

2023年4月の時点では「3. インサイト・課題定義」の段階にあった。その後、「提供価値と理想状態(UX)の定義」まで確定させ、プロジェクトは2023年9月に終了した。

# 役割

役割はデザインリードとして、本プロジェクトの進行を担当した。
カスタマージャーニーマップ作成ワークショップの実施要項、有識者ヒアリングの事前共有資料と質問、価値定義フェーズの実施概要、ワークショップ運営の振り返りまで実施した。

# 背景と課題

## 背景
CTSは2021年にリリースし、2022年12月にβ版から正規版としての機能リリースを完了した。0→1の「創る」期間を終え、1→10の「固める」フェーズに入るところであった。

## 課題
本プロジェクトは、プロダクト責任者が3か年予算の作成にあたって立ち上げた。拡大の見込みを立てるには、CTSが提供しようとしている価値が本当にユーザーの課題解決になっているのか、なっているならなぜなのかを明確にする必要があった。

## 1〜3. 注力すべきターゲットのセグメント定義
企業側と学生側それぞれのペルソナ定義のためのワークショップを実施。「ユーザーの発言した事実そのままを記録する」を注意点に掲げ、顧客の行動は事実、顧客の感情は推測として書き分けた。
また、その際既存のユーザーの声(問い合わせ、録画、アプリレビュー、過去プロジェクトのヒアリング記録)を事前情報として投入した。

## 価値提供の定義

- 価値の定義と共通認識づくりには、顧客のニーズを起点に、これまでの市場にない独自性のある価値を見つけることを重視するため、リーンキャンバスやビジネスモデル・キャンバスではなく、バリュー・プロポジション・キャンバス(VPC)を採用した。
- バリュー・プロポジションを「ユーザーの真のニーズにフィットしていて、かつ自社だけが提供できる価値」と定義し、競合のスカウト型サービスと並べて差分を見た。
- 提供価値が自社のケイパビリティ(実現する力)を超えた場合は、「なくてはならないもの」と「あったらうれしいもの」に分ける、という判断ルールを置いた。

## 指標の設計

::: figure 定義した価値が使われているかを測る(HEART) | 学生側アプリについて、観点ごとにゴール → シグナル → 指標を整理した

| 観点 | ゴール → シグナル | 指標 |
| --- | --- | --- |
| Happiness | 自分の興味の方向性がわかる → スカウトを承諾する・イベントに応募する | 承諾数・承諾率 |
| Engagement | 参加したいときに使う → 週 2〜3 回アプリを開く | DAU・MAU |
| Adoption | インターン参加のために登録する → 新規登録が増える | 新規登録数 |
| Retention | 興味の方向性を知るために使い続ける → プロフィール更新・他己分析の依頼 | 更新数・依頼数 |
| Task Success | 使いたいときに使える → 情報へのアクセスとチャットが滞りない | エラー頻度 |

::: caption メッセージ・イベント・プロフィールの各機能、企業側アプリも同じ型で整理した。出典: HEART 指標ツリー
:::
