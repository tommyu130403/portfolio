# プロジェクト概要

キャリアチケットスカウト正規版の第2四半期施策として、学生向けの募集掲載(インターン・説明会)機能を企画した。
自己PRや学生時代に力を入れたことを準備中の学生でも、企業と接点を持てる状態をつくる。

# 役割

リードデザイナーとして、要求整理からデザイン要件定義、デザイン(外部設計)、フロントエンド開発まで担当した。
また、デザイナーメンバーへのタスク指示やデザインのフィードバック、フロントエンド領域のコードレビューを実施した。

# 背景と課題

## 背景
正規版に向けて集客を広げ、学生が早期に企業と接触できるメディアにする必要があった。

| 学生側 | 準備が整っていない学生は何もアクションできず、就活を始められない。 |
| 企業側 | ユーザー数を増やして流入経路の選定に入り、契約率を上げたい。 |

## ユーザーヒアリングの設計
上記を検証するため、ユーザーヒアリングを設計した。対象は、スカウトサービスを1か月程度使い、プロフィールをある程度入力している学生である。

## 要件定義
- 既存機能の優先度を踏まえて導線を配置すること
- 募集掲載の情報を「価値観」という指標でも探せること

## プロダクトの「見え方 (プロモーション)」の設計

既存機能の機能優先度を考慮し募集掲載機能の配置箇所を検討するために、「プロダクトそのものの見え方」を考慮する必要があった。

「スカウトが来るアプリ」というプロモーションを取っていたが、募集掲載機能の追加により「スカウトがくるアプリ + 応募ができるアプリ」となるため、どのようなプロダクトとして認識してもらうべきか改めて定義した。

::: card アプリとしての「見え方」
「スカウトがくるアプリ + 応募ができるアプリ」
= **企業と複数の接点を持つことができるアプリ**
:::

::: figure 段階導入の設計 | 既存ユーザーへの影響と工数を抑えるため、「何ができるアプリか」を 3 フェーズで更新する
::: flow highlight=1
- PHASE01 スカウト > 募集
- PHASE02 スカウト + 募集
- PHASE03 キャンパスアプリ
:::

| フェーズ | 位置づけとグローバルナビ |
| --- | --- |
| PHASE01(今回) | 自己理解できて企業と出会えるアプリ。既存の構成を変えず、募集掲載(イベント)だけを追加する。ナビ: プロフィール / 自己分析 / イベント / メッセージ |
| PHASE02 | 企業と出会える手段が複数あるアプリ。自分の意思で変わる情報を「マイページ」に集約する。ナビ: マイページ / イベント / メッセージ |
| PHASE03 | キャンパスアプリ(キャリア支援)。オフライン流入でも何ができるかわかる。ナビ: マイページ / イベント / スカウト / メッセージ |

## 学生側: 「価値観」でも企業が探せる
学生自ら企業を探すとなると、知っている企業か自分が興味のある業界や業種のみとなってしまう。
本プロダクトの強みとして「自分が知らない企業との出会い = 価値観マッチング」という独自の価値提供をしているため、登録時に設定がすでにされている価値観によっても企業が検索されるような機能を反映した。

::: figure 絞り込みの流れ | 価値観 → 職種・目的の順に候補が絞られる(画面上の件数)

# 学び

大きな要となる機能の追加であったこともあり、利用する学生にとって「何ができるアプリなのか」という認識や体験の齟齬が起きないよう全体設計を考慮する必要があった。

::: card tone=accent 機能を足す前に「見え方」を決める
機能の優先度はプロダクトが何として認識されるかで決まるため、段階導入の設計はその認識を壊さずに更新するために必要な計画であった。
:::
