# プロジェクト概要

キャリアチケットスカウトの立ち上げ期に、ユーザーリサーチを行った。
企業が知りたい学生情報は何か、学生の自己分析を支援できるかを確かめるために、企業側の採用担当・営業担当、キャリアアドバイザー、学生へのヒアリングと、自己分析機能のプロトタイプ検証を実施した。

# 役割

ヒアリングの設計、プロトタイプテスト実施まで担当。

# 背景と課題

## ユーザー背景

::: grid cols=2 gap=4
::: card 学生
新卒の就活は転職と異なり、学生は自分のことがわかっていない状態から始まる。
- ミスマッチなく就活を進めるには自己理解が必要だが、自己分析の方法がわからないことが阻害要因になっていた。
- 学生は強み・自己PR・学生時代に力を入れたことを混同しやすい。強みを自力で3つ出すのは負担が大きい。
:::
---
::: card 企業
自社では出会えない学生との接点を求めてスカウトサービスを使う。
:::

::: grid cols=2 gap=4
::: card 目的

## 企業・カウンセラーへのヒアリング
企業側は、学生選定で学生時代に力を入れたことや長所を見ており、他社の選考状況や志向性も知りたいとわかった。同時に、資格はほぼ見ないことや希望条件は途中で変わっても更新されないため、信用されにくいということがわかった。
カウンセラーからは、企業を薦めるには強み・弱み、力を入れたこととその動機、将来実現したいこと(就活軸)が必要だと聞いた。

::: figure 重視する観点
| 立場 | 重視する観点 |
| --- | --- |
| 企業 | 学生時代に力を入れたこと / 長所 |
| カウンセラー | 学生時代に力を入れたこと / 強み・弱み / 就活軸 |
:::

## 学生へのプロトタイプ検証
Figmaのプロトタイプを共有し、その場でコメントを記入してもらう形で検証した。学生は、自己分析を企業公開用と自分用に分けたいと考えていた。弱みが企業に見えることには抵抗があった。

::: figure 仕様方針の比較と選択
| 項目 | 方針 |
| --- | --- |
| 自己分析ページ | 企業閲覧可の1枚構成ではなく、企業公開用と本人専用(弱みを含む)の2分割にする |
| 強み | 本人に3つ出させるのではなく、アピールポイントとして引き出し、エピソードで深掘りする |
| 就活軸 | フリーテキストではなく項目型にする |
| 集客 | 無料ベータ・モニター募集から段階的に有料化する案を検討した |
:::

# 成果

- 学生プロフィールの中核項目を整理した。基本情報、自己PR、長所短所、写真、学生時代に力を入れたこと、就活軸、自己分析(自分史・強み)である。
- 資格、選考フローの細かな粒度、希望条件は優先度を下げても良いという開発優先度の判断基準を得ることができた。

# 学び

キャリアチケットスカウトのβ版開発はアジャイル開発で進めており、リリースそのものが仮説検証だった。そのため、リサーチを開発プロセスに組み込み、仮説の確度を上げてからリリースに臨めた。
