# プロジェクト概要
::: summary
lead: キャリアチケットスカウトの立ち上げ期に、企業が知りたい学生情報と、学生の自己分析を支援できるかを確かめるユーザーリサーチを行った。
problem: 学生の多くは自分のことがわかっていない状態から就活を始め、自己分析の方法がわからないことが阻害要因になっていた。
action: 企業・キャリアアドバイザーへのヒアリングと、学生への自己分析機能のプロトタイプ検証を行った。
result: 学生プロフィールの中核項目を整理し、開発優先度の判断基準を得た。
:::

キャリアチケットスカウトの立ち上げ期に、ユーザーリサーチを行った。企業が知りたい学生情報は何か、学生の自己分析を支援できるかを、リリース前に確かめるのが目的だった。

# 背景と課題
## ユーザー背景

::: grid cols=2 gap=4
::: card 学生
新卒の就活は転職と異なり、学生の多くは、自分のことがわかっていない状態から始まる。
- ミスマッチなく就活を進めるには自己理解が必要だが、自己分析の方法がわからないことが阻害要因になっていた。
- 学生は強み・自己PR・学生時代に力を入れたことを混同しやすい。強みを自力で3つ出すのは負担が大きい。
:::
---
::: card 企業
自社では出会えない学生との接点を求めてスカウトサービスを使う。
:::
:::

## 目的とゴール

::: grid cols=2 gap=4
::: card 目的

## 企業・キャリアアドバイザーへのヒアリング
企業側は、他社の選考状況や志向性も知りたい一方、資格はほぼ見ないとわかった。希望条件は途中で変わっても更新されないため、信用されにくい。キャリアアドバイザーからは、企業を薦めるには力を入れたことの動機と、将来実現したいこと(就活軸)まで必要だと聞いた。

::: figure 重視する観点
| 立場 | 重視する観点 |
| --- | --- |
| 企業 | 学生時代に力を入れたこと / 長所 |
| キャリアアドバイザー | 学生時代に力を入れたこと / 強み・弱み / 就活軸 |
:::

## 学生へのプロトタイプ検証
Figmaのプロトタイプを共有し、その場でコメントを記入してもらう形で検証した。学生は、自己分析を企業公開用と自分用に分けたいと考えていた。弱みが企業に見えることには抵抗があった。

::: figure 仕様方針の比較と選択
| 項目 | 方針 |
| --- | --- |
| 自己分析ページ | 企業閲覧可の1枚構成ではなく、企業公開用と本人専用(弱みを含む)の2分割にする |
| 強み | 本人に3つ出させるのではなく、アピールポイントとして引き出し、エピソードで深掘りする |
| 就活軸 | フリーテキストではなく項目型にする |
| 集客・課金 | 無料のβ版でモニターを募集し、段階的に有料化する案を検討した |
:::
