# プロジェクト概要

キャリアチケットのサービス間で、ユーザーが登録し直さずに行き来できるよう、連携を整えた。キャリアチケットスカウトのユーザーを起点に、2つの施策を進めた。
- 施策①: キャリアチケットエージェントの面談予約への送客
- 施策②: 自社セミナーへの集客

期間は、2024年10月の初回すり合わせから2025年3月の効果検証終了までの約5.5か月。
本番リリースは2025年3月。

# 役割

12名・4つの社内組織にまたがる体制で進めた。
最終合意者、要件確認者(プロダクトオーナー)、全体管理と実装を担うエンジニア、各組織のレビュアー、外部設計を担うデザイナーで構成。

自身は初動のプロジェクトマネジメント(プロジェクト要件の定義)と外部設計(画面と操作の仕様)のレビューを担った。
- 関係者の特定と連携
- プロジェクト憲章(目的・範囲・体制をまとめた文書)の作成
- 施策計画書(デザインドック)2本の作成
- 外部設計を担当するデザイナーへのタスク依頼と進捗管理

デザイン制作は別のデザイナーが担った。
日次の進行・工数管理はエンジニアが担った。

# 背景と課題

## 背景
- キャリアチケット全体で集客効率を高め、学生あたりの売上を上げる必要があった。
- 集客コストが膨らんでいた。エージェントとセミナー事業の集客経路をスカウトに寄せ、そこからイベント・セミナーに応募できる状態を目指した。
- サービス間の送客効率が停滞していた。別サービスを使うたびに登録し直す必要があった。
- セミナーは、競合の出稿強化と参加率の低下で参加獲得コストが高騰していた。スカウトからセミナー予約までのステップが多く、既存導線からの予約はほとんど生まれていなかった。

## 目的とゴール

::: grid cols=2 gap=4
::: card 目的
- 施策①: スカウト経由の面談実施率の上昇
- 施策②: スカウト経由のセミナー予約率の上昇
:::
---
::: card ゴール
- 施策①: スカウトのユーザーを、LPを介さず直接エージェントの面談予約ページへ送客できる状態にする
- 施策②: 募集掲載機能に自社セミナーを載せ、学生へセミナー送客のスカウトを送れる状態にする
:::
:::

## 制約
- 3つの組織にまたがるコードレビューが必要で、リリースの目処が読みづらかった。
- エージェント側の人員がボトルネックになり、送客できないリスクがあった。
- 施策②はセミナー集客に間に合わせるため、11月中旬が期限だった。
- 開発工数の都合で、一部の機能をスコープから外した。

# 取り組み

::: figure 登録し直す導線をなくす | スカウトサービスのユーザーが、LPや別サービスへの再登録を経ずに、面談・セミナー予約まで到達できるようにした
::: beforeafter 施策① | エージェント面談への送客
before: スカウトを受信 → サービスLP → [!エージェントに新規登録(情報を再入力)] → 面談予約
note: LP → 登録で大半のユーザーが離脱
after: 送客スカウトを受信 → [+送客URLから面談予約ページへ直接]
note: LPと再登録をスキップ
:::
::: beforeafter 施策② | 自社セミナーへの集客
before: ポップアップ・メールで告知 → セミナーLP → [!別サービスのアカウントでログイン / 新規登録] → 予約
note: 予約のコンバージョン率はほぼゼロ(メール経由もごくわずか)
after: 募集掲載・スカウトでセミナーを案内 → [+スカウトサービス内でそのまま予約]
note: 既存の募集掲載機能に相乗りし、スカウトサービス内で予約まで完結
:::
:::

### 施策①: 面談送客の導線設計
管理画面から、条件に合う学生へ面談送客のスカウトを一括送信できるようにした。CSVでの候補者リスト作成にも対応した。学生は送客URLから、LPを介さず面談予約ページへ遷移する。送るスカウトは、卒年、エージェントサービス登録からの経過日数、メッセージIDで出し分けた。

::: figure 面談送客スカウトの送客フローと主な要件
::: flow 送客フロー highlight=4
- 管理画面で対象学生を抽出
- 面談送客スカウトを一括送信
- 学生が送客 URL をタップ
- 面談予約ページへ直接遷移
:::
::: caption 主な要件

| 項目 | 要件 |
| --- | --- |
| 送客URL | APIで発行。LPを経由せず面談予約ページへリダイレクト |
| 出し分け条件 | 卒年 / エージェントサービス登録からの経過日数 / メッセージID |
| 経過日数の扱い | 7日以内は追いかけ、8日以降は掘り起こし |
| 送信対象 | 優先度別にセグメント分割し、面談枠に合わせて段階送信 |

::: caption 検討して見送った案
- ポップアップ配信(行動分析ツール)… 送客スカウトの方が反応率が高いため不採用

:::

### 施策②: 既存機能への相乗り
募集掲載機能に自社セミナーを掲載できるようにした。既存の画面に相乗りし、表示する項目と文言だけをセミナー用に切り替えた。

::: figure 既存の募集掲載機能に相乗りするための表示・文言ルール
::: grid cols=2 gap=4
::: caption 表示ルール

| 要素 | セミナー掲載時の扱い |
| --- | --- |
| 価値観・業界・職種 | 非表示 |
| 目的 | セミナー用の項目を追加 |
| おすすめ順 | 優先度を最下位に(UX精査前のため露出を抑制) |
| 「この企業について」 | ボタン非表示 |
---
::: caption 文言の出し分けルール

| 本選考・インターン | セミナー |
| --- | --- |
| 応募 | 予約 |
| 企業 | 運営局 |
| 参加・参加予定 | 参加・参加予定(変更なし) |
:::
::: caption 工数・納期による割り切り
- ステータスは「イベント応募」のまま(専用ステータスは追加しない)
- イベント関連データの連携はシステム対応せず、運用でカバー

:::

# 成果

- 本番リリースは2025年3月に完了。6つのマイルストーンのうち5つが期日どおりか翌日に着地。遅延は外部設計の1件のみで、全体の進行に大きな影響はなかった。
- 最も活発な層で、送信からクリックへ進んだ割合(展開率)が改善した。一方、活発な層(約0.9倍)と休眠中心の層(約0.7倍)では悪化した。
