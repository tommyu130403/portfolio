# プロジェクト概要

24卒のデザイナー志望学生を対象に、3日間のサマーインターンシップを企画・運営した。
(「モノをつくる」その先へ。組織と事業の課題を解決するデザイナーサマーインターンシップ)

テーマは「デザイナー就活の課題解決」とした。学生は2〜3人のチーム(全4チーム)を組む。就活生側と企業側の双方の課題を整理し、施策として提案に落とし込んだ。

| 項目 | 内容 |
| --- | --- |
| 期間 | 2022年5月(企画開始)〜2022年9月(本番) |
| 形式 | 事前説明(オンライン)+本番3日間(オフライン) |
| 提供したい体験 | デザイン提案に必要な情報を整理し、施策として落とし込む体験 |

# 背景と課題

## 背景

- 新卒デザイナーは、市場の母数がそもそも少ない。その中で優秀層を獲得したかった。
- 社内では新卒デザイナーの受け入れ態勢が整っていなかった。そのため、教育のナレッジや仕組みが蓄積されていなかった。

## 目的とゴール

::: grid cols=2 gap=4
::: card 目的
事業の視点を持ち、自走できる学生を獲得することが目的である。対象は、プロダクトデザイナーとしてのポテンシャルがある学生とした。
:::
---
::: card ゴール
- 参加者を就業型インターンと本選考につなげ、新卒デザイナーの採用を実現する(目標人数は非公開)。
- 学生に「**デザインをサービスの核にする**」というメッセージを持ち帰ってもらう。
:::
:::

## ターゲット

- サービスを作る中で、デザインの可能性に気づき始めた学生
- デザイナーを目指しつつ、ディレクションや組織改善など他のスキルも磨きたい学生

## スコープ外

次の項目は評価の対象外とした。

- 新規事業の開発・デザイン
- ビジネスモデルや緻密な事業計画書

## 制約とリスク

| 項目 | 内容 |
| --- | --- |
| 人数 | 当初は最小6人程度、上限12人と想定した(実際の人数は調整した)。上限はメンターが対応できる人数で決まる。母数が少なく、開催できるか不安があった。 |
| 日程 | 競合他社のインターンが集中する時期を避けた。大学の夏季休暇の傾向も踏まえ、9月第2週を選んだ。 |

# 取り組み

::: flow 進め方 highlight=0
- 企画の方針を決める
- 3日間のプログラムを設計する
- 当日の進行とメンタリング
:::

### 企画の方針を決める

仮説は「デザイン経営を体験すれば、今後求められるデザイナーのスキルが身につく会社だと伝わる」である。体験させたい要素は次の3つとした。

- サービスの本質的な問題から考える
- ユーザーとの距離が近い
- 作ったら終わりではない

初期案は「既存事業の改善案づくり」+2.5日の構成だった。最終的に「デザイナー就活の課題解決」+3日間オフラインに変更した。学生がユーザーの立場になって考えられるよう、題材の難易度を下げて適切な水準に合わせたためである。

### 3日間のプログラムを設計する

::: figure 3日間のプログラム
| 日程 | 内容 |
| --- | --- |
| 事前(オンライン) | 事前説明 |
| 1日目 | チームビルディング、市場調査(象限ごとのカスタマージャーニーマップ作成)、社内の法人営業担当・キャリアアドバイザーへのヒアリング、就活生と企業のセグメンテーション、課題のあたり付け |
| 2日目 | バリュープロポジションキャンバス作成、プロトタイピング、社内の法人営業担当・キャリアアドバイザーによるユーザーテスト、発表準備 |
| 3日目 | ブラッシュアップ、発表(1チーム10分+質疑5分)、総評、振り返り、懇親会 |
:::

### 当日の進行とメンタリング

全体進行とメインメンターを担当した。助言やフォローの前に、学生が「何がわからないのか」「何をしたいのか」を確かめ、どの工程で助けを求めているかを把握してから関わるようにした。メンターは答えを教えず「なぜ」を問いかけ、考えることは学生自身に任せる方針とした。

# 学び

実施後の振り返り(KPT)で、次の課題が見えた。

- ワークがフレームワークに当てはめる作業になった。具体的なニーズを深掘りできなかった。
- ワークの時間が長かった。学生がメンターと話せる時間が、懇親会まで取れなかった。
- インターン後の受け皿がなかった。次の接点をインターン中に確保できなかった。
