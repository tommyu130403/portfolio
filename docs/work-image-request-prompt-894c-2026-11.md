# 894c 入力ルールの画面キャプチャ依頼文(2026-11-17 作成)

現職の資料を見られる別端末(会社のアカウント)の Claude に、下のコードブロックをそのまま貼る。返ってきた画像と報告は、このリポジトリのセッションに貼れば作品本文へ配置する。

```
## 依頼: 個人のポートフォリオ掲載用に、アプリの入力画面のキャプチャを 1〜3 枚用意してほしい

### 目的
個人のポートフォリオサイトの作品「キャリアチケットスカウトの立ち上げ」(2021年8月に学生向けアプリをリリース)に、「アプリ内の入力ルール」という表を載せている。表だけでは実際の画面での見え方が伝わらないため、入力の上限(文字数・個数)が画面のどこに出ているかが分かるキャプチャを表の下に添えたい。

### 表の内容(この上限が見える画面を探す)
| 機能 | 上限 |
| --- | --- |
| 自分史・経験カード | 無制限 |
| ガクチカ(学生時代に力を入れたこと) | 500 文字 × 最大 3 つ |
| 強み | 15 文字 × 最大 5 つ(3 つ推奨) |
| 自己PR | 500 文字 × 1 つ |

### 集めてほしいこと
| ID | 画面 | 優先 |
| --- | --- | --- |
| S1 | 強みの入力画面(15 文字・最大 5 つ・3 つ推奨が見える) | 高 |
| S2 | ガクチカの入力画面(500 文字・最大 3 つが見える) | 高 |
| S3 | 自己PRの入力画面、または自分史・経験カードの一覧 | 低 |

探す場所の例: Figma の学生アプリのファイル(初期リリース版のページ)、仕様書・画面一覧、リリース告知、ストア掲載用の画像。2021 年 8 月の初期リリース時点の画面が望ましい。見つからなければ、その後の版でも上限の表示が同じならよい(その旨を書く)。

### 成果物
1. 画面の書き出し画像: PNG、1 画面 1 枚、スマホ 1 画面分(縦長のまま・端末の枠は不要)。ファイル名は `pf-cts-input-<S1|S2|S3>.png`
2. 次の表 1 つ
| ID | 判定(見つかった / 一部 / 見つからない) | 何の画面か(1 行) | 時期(初期リリース版か・後の版か) | 出典(資料名・ページ・日付) | 社外に出してよいか(はい / いいえ / わからない。根拠があれば添える) |

### 完了条件
- S1・S2 の 2 行に判定と出典がある(S3 は任意)
- 「見つからない」の行は、探した場所を書いてある

### 確かめ方
- 画像を開き、上限の文字数・個数が読める大きさで写っていることを目で確かめる
- 時期は資料の日付・ページ名などで確かめたものだけ書く。推測で埋めない

### やらないこと
- 実在の学生・企業担当者の氏名、顔写真、メールアドレス、実際の入力内容(本人の自己PR 文など)が写った画面は書き出さない。写る場合はダミーの文に差し替えるかぼかす。できなければその画面を外す
- 数値(利用者数・入力率など)は書かない
- 資料の編集・コメント・共有設定の変更をしない
- 書き出した画像や報告を、この端末の外(個人のメール・クラウド・チャット)へ送らない。受け渡しは本人が行う

### 止まる条件
- 資料にアクセスする権限が無い、または社外秘の表示がある資料しか見つからない → その時点で報告して止まる
- その画面を個人のポートフォリオに使ってよいか(就業規則・秘密保持・広報や上長の確認が要るか)がわからない → 書き出す前に報告して止まる
- 探す場所の例をすべて探しても S1・S2 とも見つからない → 探した場所を報告して止まる
```
