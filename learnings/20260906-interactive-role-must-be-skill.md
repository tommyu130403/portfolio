# ユーザーとの対話が本質の役割はサブエージェントではなく skill にする

- 文脈: 「作業を受け付けて要件を整理する PM / ディレクター席」を新設するにあたり、既存6席と同じく `.claude/agents/*.md` のサブエージェントにするか、`.claude/skills/` の skill にするかを決める必要があった。
- 観測: サブエージェントは起動時のプロンプトだけで完結して結果を返す片道の仕組みで、実行中にユーザーへ聞き返せない。既存の `scope-planner`（依頼を要件へ縮約する席）も同じ制約を持ち、リポジトリを読んでの縮約はできるが、ユーザーにしか答えられない穴は埋められない。CLAUDE.md §6-1 はメインセッションを「計画専任」と定義しており、対話はメインセッション側の責務に当たる。
- 結論: 役割の本体が「往復の対話」なら skill にしてメインセッションで動かす。サブエージェントにするのは、入力が確定していて出力がレポートで足りる役割だけ。新設した受付席は `.claude/skills/director` に置き、CLAUDE.md §0-4 で必ず通すよう必須化した。
