# learnings/ — 学習ループ運用

作業で得た学び・失敗・気づきを蓄積し、検証を経て lessons skill の「失敗パターン」へ昇格させる場所。**1学び1ファイル**。

## 形式（1ファイル1学び）
ファイル名: `<yyyymmdd>-<kebab-slug>.md`。本文は以下の4項を必ず含める。

```markdown
# <一行タイトル>

- 文脈: どの作業のどの状況で起きたか
- 観測: 実際に見た事実（コマンド出力・エラー・diff など）
- 結論: 次に同じ状況で取るべき一手
- 事実確認: VERIFIED（実行して確認）/ REASONED（推論）/ ASSUMED（未確認の仮説）
```

## ルール
- **重複を作らない**: 既存ファイルに同趣旨があれば新規作成せず追記・更新する。
- **誤りは削除する**: 後で誤りと判明した学びはファイルごと削除する（残さない）。
- **観測を書く**: 「〜のはず」は結論に書かない。観測に基づかない主張は ASSUMED と明記。

## ライフサイクル
```
draft（気づいた時点で下書き）
  → 検証（別の機会に観測で裏取り / 再現確認）
  → 承認ゲート（下記の昇格基準を満たすか判定）
  → 昇格: lessons skill（coding-lessons / research-lessons）の「2. 失敗パターン」へ移動
  → 破棄: 誤りと判明したものは削除
```

## 昇格基準（いずれかを満たしたら lessons skill へ）
- 同じ失敗が **2回以上再発** した
- **観測で裏取り済み**（VERIFIED）
- 特定タスクに閉じず **一般化可能**

昇格したら learnings 側の元ファイルは削除し、lessons skill 側に一本化する（二重管理しない）。

## 関連
- コード作業の失敗パターン: `.claude/skills/coding-lessons/SKILL.md`
- 調査作業の失敗パターン: `.claude/skills/research-lessons/SKILL.md`
- 記録は `/learn` skill を使うと定型で書ける。
